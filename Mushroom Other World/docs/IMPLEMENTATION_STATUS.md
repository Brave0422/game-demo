# v0.3 开发试玩版实现状态

更新：2026-10-12。入口是根目录 `project.godot`，Godot 4.7.2 标准版，Compatibility 渲染。Windows x86_64 试玩包在 `builds/windows/`，可脱离编辑器启动。产品目标仍以 PRD 为准；此页记录已经写入工程的行为，不代表所有人工验收完成。

## 已落地的游戏流程

中文菜单 → 角色选择 → 蘑菇草地 S1–S4 → 地下城 S5–S7 → 两阶段孢子大王 S8 → 胜利结算。失败后可恢复最近检查点，暂停页支持继续、重试和返回菜单。设置提供总音量、音乐、音效、全屏与镜头震动，失焦自动暂停。

- 共用移动控制器实现加速/减速、跳跃截断、离地宽限和跳跃缓冲；比尔支持八方向射击及地面趴下，洛克人支持蓄力、四槽武器与独立能量。
- 九份武器配置：比尔普通枪/M/S/L/F，洛克人基础炮/切刃/冰波/火焰。弹体采用物理扫掠、实体遮挡和攻击组去重；散弹、激光、切刃、冻结与火环各自有独立规则。
- 五类怪物有巡逻、喷吐、俯冲、滚动与盾壳状态；仅滚兽持续接触伤害。冻结取消攻击，解冻带宽限。受伤同帧只取最大值，普通无敌不能抵挡落坑。
- 固定 43,520 单位关卡、八区段、40 个静态敌人和两场各六只的有限遭遇战。四组移动平台、两组开关/门、两条可选支路、三类破坏物、角色映射武器箱与回复道具已配置到场景。
- CP0–CP5 使用稳定 ID 保存世界、掉落、装备和分段时间；恢复重建活怪与平台。内容用时回滚失败段并扣除支路，挑战总用时保留失败尝试。会话进度不写硬盘，只有设置和成绩持久化。
- Boss 具有扑砸、扇形弹和地面波，半血后加入组合攻击；核心窗口、攻击总额限制、失败重试和双方同帧死亡优先胜利已实现。
- 已接入中文字体、分层背景、音频总线、区域音乐切换、攻击/受伤/胜负反馈。人物、部分怪物与 Boss 使用可编辑的代码原生分层图形，详见美术来源说明。

## 工程规范和审查入口

用户追加的两项要求已写入 [CODING_STANDARDS.md](CODING_STANDARDS.md)，并同步到 PRD、技术方案、工程目录与验收清单。场景和专属脚本就近组织；Resource 保存设计数据，实例保存运行状态；全局服务限定为会话、存储、音频。变量、循环变量、方法与关键节点均提供中文说明，场景节点使用 `editor_description`。

| 调整内容 | 修改位置 |
| --- | --- |
| 角色移动参数 | `resources/characters/character_data.gd`、角色 `.tres` |
| 武器伤害、射速、耗能、上限 | `resources/weapons/` 中九份 `.tres` |
| 怪物血量、预警、恢复、移动速度 | `resources/enemies/` 中五份 `.tres` |
| 固定对象位置、检查点、箱槽、关联门 | `scenes/levels/mushroom_world.tscn` |
| 可编辑 TileMapLayer 地形 | `scenes/levels/terrain.tscn` |
| 区段边界、标题与关卡宽度 | `resources/levels/level_data.gd` |
| 遭遇战波次 | `resources/encounters/e1.tres`、`e2.tres` |
| Boss 状态和时序 | `scenes/bosses/spore_king.gd` |
| 计时、快照、重试 | `core/game_session.gd`、`scenes/levels/mushroom_world.gd` |
| 输入、分辨率、碰撞层、全局服务 | `project.godot` |
| 音量与持久化 | `core/save_service.gd`、`core/audio_manager.gd` |

`tools/build_scenes.py` 和 `tools/build_terrain.gd` 是初稿生成工具，游戏运行时不执行。后续在编辑器修改场景后，不应直接重新生成覆盖人工编辑。`.tools/` 仅存本机引擎与开发依赖，不随游戏导出；换机可通过 `GODOT_BIN` 指定引擎，并安装匹配的 Windows 导出模板。

## 已知边界与下一轮验收

1. **14–18 分钟目标尚未验证。** 熟悉地图的自动输入主线用时约 3–4 分钟，显示关卡节奏仍需重点校准；不能用该结果冒充首次体验样本，也不能靠增加等待或死亡时间凑数。按 QA 清单招募至少六名首次玩家、每角色至少三份，记录分段时间后再调整内容。
2. 完整关卡自动输入允许正常取得特殊武器；两角色基础武器已单独通过 Boss 测试。仅基础武器整关、所有边界组合和真实键盘手感仍需补充人工覆盖。
3. 当前画面满足非像素且具备动作/危险提示，但与参考图的完整手绘质感、动作精修仍有差距，不作为最终美术验收版本。
4. 音频已接入并实际有窗口运行；主观音量、密集射击混音及循环接缝仍需试听。Headless 测试主动不播放音频，避免无设备驱动的解码线程影响测试退出。
5. 已完成本机运行和导出测试；没有宣称在另一台干净 Windows 机器通关，也没有宣称所有硬件均达到 60 FPS。非 16:9、全屏与高弹量性能仍按 QA 清单逐项记录。

实际自动化、画面证据及各项覆盖范围见 [验证报告](validation/IMPLEMENTATION_REPORT.md)。
